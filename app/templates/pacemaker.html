Planned migration to managed Corosync transport

Convert an adopted or custom configuration to the reviewed knet configuration. This replaces custom transport options and briefly stops cluster communication. Authentication keys, the existing TLS witness and Pacemaker resources are retained. First quiesce all nodes: Pacemaker must stop every managed application. Resources stay in standby until you explicitly resume them.

A 240-second host timer restores the original Corosync file after an interrupted switch and leaves Pacemaker stopped. GUI recovery verifies every member has quorum before restarting Pacemaker. Application standby remains in place for review.

Auto Start for cluster daemons

Choose the host systemd recovery policy for Corosync, Pacemaker and an installed qdevice client. Failure recovery waits 10 seconds and is limited to three starts in five minutes. Explicit systemd stop stays stopped; maintenance and standby resource settings remain under Pacemaker control. This does not independently restart application resources.

Conflicting proxy Auto Start flags for applications owned by Pacemaker are disabled when applying this policy. Use Pacemaker resource controls for those applications.
